# Quasi Atlas · 功能导航与信息架构（2026-10-24）

## 核心原则

**功能按用户的任务归类，不按 G0–G6 研发阶段堆叠。** G 阶段用于说明可信程度、验证进展和研发里程碑，不能代替用户寻找入口的功能分类。

保留现有的单画布工作台：观察 / 学习 / 研究是工作台内部的操作模式，不应扩张成三个互不相通的产品。交互数学引擎、科学契约、E0/E1 标签和本地 Notebook 均保持原有实现。

## 一级导航（稳定，不随功能数量增多）

- **发现**：向新用户解释价值，六个生活场景作为低门槛入口。
- **探索工作台**：一幅数学画布，主题切换抽屉，观察 / 学习 / 研究面板。
- **功能目录**：所有可使用的功能 + 工程原型的明确说明；全文搜索、按功能目的筛选、直接定位真实入口。
- **研究路线**：G0–G6 当前真实里程碑、限制、未解决的证据要求、E0–E4 科学级别。

不要给每个 G 阶段单独增加一级导航项，也不要让用户只能通过“研究路线”寻找现有功能。

## 功能目录分类（第二级）与入口规则

| 类别 | 当前条目 | 打开行为 |
| --- | --- | --- |
| 生活中的数学 | G1 六个生活教学场景 | Studio → 学习 → 对应课程 |
| 数学世界与探索 | 实时观察、全部 PRESETS 数学世界 | Studio → 观察 → 对应数学预设 |
| 实验与检验 | 临界点候选、三档精度、H0、G6 六题自测 | Studio → 研究 → 对应实验/展开模块 |
| 发现记录与输出 | G2 Notebook、研究数据和可视化导出 | Studio → Notebook 弹窗 / 研究工具展开区 |
| 科研阶段与成果 | G3/H1、G4、G5、G6 和完整路线 | 研究路线 → 展开特定里程碑 |

用户可输入标题、G 阶段代号、中文功能词汇或英文术语寻找结果。研究代码尚无 UI 时必须标记为**未提供交互页面**，点击只能查看对应可信的研发进度，禁止做空白页或“可直接体验”按钮。

## 新增功能时必须履行的四项约束

1. **先定义用户意图**（学习 / 探索 / 验证 / 记录 / 查看研究状态）。功能与原有数学流程共同工作，不为每个功能新增一级导航。
2. **注册单一数据源**：在 `src/feature-catalog.js` 中向对应 `FEATURE_SECTIONS` 添加条目，含唯一 `id`、名称、简述、适当的证据/成熟度状态、关键词、真实跳转 `kind/value`。G1 课程和 PRESETS 由现有数据自动生成，不需要维护第二份名单。
3. **为交互功能接通真实目标**：优先复用 Studio 原有 DOM id / 事件，勿复制数学算法、绕过证据等级、制造第二个实际功能入口；对新类型扩展 `openFeature`，更新自动化可达性测试。
4. **为每个入口提供验收**：检索命中、点击到达、桌面与 390px 移动端无溢出、JS 无错误、浏览器后退 / 链接恢复，以及现有数学和 G0–G6 科研测试无回归。

当前可访问 URL：`?screen=catalog`（功能目录），`?screen=roadmap&milestone=G5`（直接展开里程碑）。在非输入框中输入 `/` 可打开功能搜索。

## 本次已实施的边界

- 目录及按钮是真实产品功能，不是计划中的假按钮；G4/G5 等后端原型不冒充前端实验工具。
- 没有改动数值算法、Notebook 存储、科研状态门禁、账户系统或部署配置。
- 目录专项验收：`node scripts/catalog-smoke.mjs`，需启动本地 Vite 服务；共 8 项交互核对。
- 既有验收：`npm run test:studio`、`npm run test:ui`、`npm test`。
- 浏览器测试截图：`docs/ui-catalog-desktop.png`、`docs/ui-catalog-mobile.png`。

## 后续架构改进建议（尚未实施）

- 在功能数量持续增长后，加入可复用的二级上下文导航和“最近使用 / 收藏”，但应先有真实使用数据，不宜预建复杂偏好系统。
- 重构路由管理，把 `screen`、`life`、`world`、`milestone` 的 URL 状态合并为可测试的单一状态模型，以提高 Back/Forward 一致性。
- 为 H1、G4、G5 在有成熟的独立交互流程后再升级条目状态；科研发布 Gate 的 BLOCKED 不能因可视化存在而被绕过。


## 2026-10-24 · 首次使用体验二次修正

以“用户一进来就能玩”为中心，而不是让用户先选一个产品功能。首页直接呈现使用真实 G0 数学场和 Marching Squares 算法生成的群岛、水位滑杆、有限网格闭合边界数。用户滑动后在同屏看到变化才显示下一步；进入真实数学工作台后，可点击地图寻找某一点的数值，并自然进入 G1 生活数学学习旅程。**进阶功能始终可以使用**，所谓“解锁”是按用户进度逐步提示，而非账户关卡或权限锁。

一级视觉导航缩减为“开始玩 / 自由探索 / 更多”；“更多”展开“全部功能 / 研究路线”。这不删除既有目录或科研内容，只减少认知成本。原 G0–G6/E0–E4 证据要求与所有数值算法接口保持不变。

验收运行 `npm run test:first-play`（页面先自动可见、交互后变化、渐进按钮、继续地图、点击观察点、转入课程及 390px 移动端）；传统功能目录、UI、Studio、全部数学测试同时回归。
